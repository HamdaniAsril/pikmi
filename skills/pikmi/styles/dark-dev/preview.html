from kelar import Client, Backoff

client = Client(token=os.environ["KELAR_TOKEN"])
client.retries = Backoff(base=0.5, max=8)
client.deploy(service="billing-service", ref="main")

What happens on every push

Three things kelar does without being asked, and where to see each one.

A preview for every branch

Each push builds the branch and gives it its own link. Previews expire after seven days unless you keep them.

fix-retry.billing.kelar.example
Open the console →

Retries that back off

A flaky step gets three tries, waiting longer each time, before the build is marked as failed.

retries = "backoff"
Read the release note →

Rollback in one command

Point production back at the last build that passed. Nothing is rebuilt, so it takes as long as a redirect.

$ kelar rollback
See the quickstart →

What shipped lately

Small releases. Every change to the CLI, the config and the SDK is listed here.

  1. v2.4.014 Oct

    Preview deploys for every branch

    Every push builds a preview with its own link. Previews expire after seven days; change the window with expire_after in kelar.toml.

  2. v2.3.230 Sep

    Retries back off on their own

    Flaky build steps retry up to three times, waiting longer between attempts, up to 8 seconds. Set retries = "off" to fail fast.

  3. v2.3.012 Sep

    One-command rollback

    kelar rollback points production at the last build that passed, without building again.

From zero to a preview link

The whole quickstart. Four commands, one file.

1Log in 2Add kelar.toml 3Open a preview 4Roll back
Step 1

Log in

The CLI opens a browser tab to confirm, then stores a token for this machine.

$ kelar login
✓ logged in as you@example.com
Step 2

Add kelar.toml

Run kelar init at the root of the repo. It writes a config with your build command and production branch.

$ kelar init
✓ wrote kelar.toml (service: billing-service)
Step 3

Open a preview

Push any branch, or deploy the one you are on. The link appears in the console and in the command output.

$ kelar deploy --preview
✓ preview ready at fix-retry.billing.kelar.example
Step 4

Roll back

If production breaks, point it at the last build that passed. Nothing is rebuilt.

$ kelar rollback billing-service
✓ production now serves d-8e7c4
